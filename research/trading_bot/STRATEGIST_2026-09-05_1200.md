## What was built (T52 — DONE)

`scripts/trading_bot/input_recency_alarm.py`, read-only, 13 instruments across 4 lanes.

For each instrument it reports the age of the **newest input row — from the row's own timestamp
field**, never file mtime — against that instrument's **declared** cadence, and exits non-zero on
any STALE. mtime is a fallback and is printed with the label `MTIME_FALLBACK(proxy, not a row
timestamp)`; a corrupt ledger is `UNREADABLE`, an empty or absent one is `MISSING`. Nothing is
allowed to be silently OK.

Two design points that are load-bearing, both selftested:

1. **Weekend grace, per-instrument.** Business-daily collectors (T30, T33, T45, BASKET1, T4) have
   weekend hours subtracted before judgement, so a Friday-stamped ledger read on a Saturday is OK
   while a 24/7 feed at the same calendar age is STALE. Without this the alarm would cry wolf every
   weekend and be muted within a week.
2. **Date-only stamps are read as END of day.** That is deliberately the conservative side: it can
   under-report age by up to 24h, never over-report it. An alarm that false-alarms gets ignored;
   this one is built to be believed when it fires.

**Hermetic selftest: ALL_PASSED (9/9)**, including the two the task named — a synthetic stale feed
must be caught, and the exact 09-02 arena shape (a live busy process, a fresh sibling `runtime.log`,
and a fresh mtime **on the ledger file itself**, with a 56h-old newest row) must still be reported
STALE from the row timestamp. Both caught.

**Wired into the tick harness** (`scripts/agent_graph/durable_tick.sh`, backup
`.bak-20260905-t52`, `bash -n` clean, `--canary-selftest` ALL_PASSED, block rehearsed standalone):
the alarm runs BEFORE the thinking chunk, its table is appended to the agent's prompt, STALE names
are logged to the tick log, and the heartbeat line now carries `stale={…}`. It is **never fatal** —
a failing alarm reports `ALARM-ITSELF-FAILED-rc<n>` rather than skipping a tick. The prompt block
explicitly forbids the agent from "fixing" a STALE instrument by restarting, re-activating,
re-epoching or resolving anything: observing is the whole job, restarting is an owner decision.
