## 3. Fault found and fixed this tick — NEWSDESK false ticker attribution

`world_reader.read_yahoo_headlines()` pulls Yahoo's **per-ticker** headline RSS across the
18-name frozen watchlist and tagged **every returned item with the ticker whose feed it came
from**. Yahoo's per-ticker RSS in fact returns general market news. Measured on the live
00:00 pull: **10 of 19 ticker attributions were false — 53%.** Examples: *"Why Goldgroup
Mining Stock Soared on Wednesday"* tagged **NVDA**; *"Broadcom's Outlook Weighs on Stock"*
tagged **GOOGL** (the one ticker in the universe it is *not* about, while AVGO — which is —
went untagged).

`tickers` is the join key between a headline and the tradable universe; it is what the
proposing agent reads to decide *which instrument* a story is about. A false tag invites a
frozen proposal on a name that had no news at all. No automated code path consumes the field
(grep: no consumers outside `world_reader`), so the blast radius is the agent's read — which
is the whole instrument, since NEWSDESK1 *is* an agent's discretionary read.

**Fix (reading surface only, same class as the 09-02 sort fix).** Subscription provenance is
preserved in a new `feed_ticker` field; `tickers` now means *mentioned* and survives only on a
word-boundary symbol match or a company-name alias match (`Broadcom`→AVGO, `Alphabet`→GOOGL, …).
Event ids are `sha256(source|headline|link)` and are unchanged, so every ledger reference still
resolves; no frozen rule, proposal, resolution or scoring path was touched.

- Hermetic selftest extended: `ticker_attribution_verified` (false tag dropped, provenance kept,
  true symbol AND alias mentions retained) → `newsdesk selftest` **ALL_PASSED: true**.
- Live re-read: 19 tags → **10, zero false**; the single non-symbol survivor is the correct alias
  hit (`Microsoft` → MSFT). Feeds: SEC_8K 40, YAHOO_RSS 299, GOOGLE_NEWS 75, COINGECKO 15, **0 errors**.

**Ledger consequence:** the 09-02 regime break already restarted this instrument's forward clock;
this fix lands inside the same not-yet-scored regime, so no *additional* break is stamped. Pre-09-02
rows stay (they were forward-frozen before outcome and that property is intact) and must never be
pooled with post-fix rows.
